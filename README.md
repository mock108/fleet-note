# Fleet Note

Uberのpayments_order CSVを、ブラウザー内だけで整理するダッシュボードです。

[公開サイトを開く](https://mock108.github.io/fleet-note/)

## 使い方

GitHub Pagesを開き、「CSVを読み込む」からUberのCSVを選択します。複数ファイルを追加でき、同じ取引IDは1回だけ集計します。同一IDで内容が違う場合は取り込みを止めて知らせます。

- **ダッシュボード**：日別・月別グラフ、報酬内訳、現金、精算残高、完了件数、取引検索。
- **口座振り込み計算**：項目ごとの切り替え、Uber精算の反映、移動済み現金と手元に残す金額。
- **確定申告・CSV出力**：月別集計、明細、元列のデータ、計算結果をUTF-8 BOM付きCSVで出力。

上部の期間フィルターは3タブとCSV出力に共通です。デモは架空データです。

## 集計の定義

金額は整数の銭単位で集計し、表示時に円へ変換します。CSVの決済時間に書かれた日付で集計します。

- 受領現金 = CSV「受け取った現金」の符号反転。Uberの精算上のマイナスを、手元の現金としてプラス表示。
- Uber精算残高 = CSV「支払い額」の合計。銀行への実入金・引落しを確認した数字ではありません。
- 報酬総額 = 支払い額 − 現金欄 − 通行料返金 − サービス料。税込・サービス料控除前。
- プロモーションは合計とクエストを二重計上しません。合計からクエストを引き、その他プロモーションとして表示します。
- 未知の内訳・不一致は「その他・未分類」に差額を表示します。金額の一致だけで内訳の分類が正しいと判断しないでください。
- 完了件数は備考に `completed` を含む取引の乗車IDを重複除去して集計。調整取引などは取引件数にのみ含めます。

## 現金の移動計算

`今回の現金移動 = 選択した項目の合計 − 事業口座に反映するUber精算 − すでに移した現金 − 今回は手元に残す金額`

Uber精算が事業口座に入出金される前提です。負の精算は事業口座から支払われる想定なので、その分も現金を入れる計算になります。正の結果は事業口座へ、負の結果は事業口座から手元へ戻す金額です。銀行の操作は行いません。精算の入出金先が別口座の場合は反映トグルをオフにしてください。

通行料返金は初期状態では除外します。それ以外は初期状態で含みます。個人の帳簿・立替処理に合わせて設定してください。

## プライバシーと保存

サーバー処理、外部ライブラリー、解析タグ、外部フォント、外部APIは使用しません。CSVの読み込み・集計・ダウンロードはブラウザー内だけで完結します。データを読み込む前のサイト配信にはGitHub Pagesへの通常の通信が発生します。CSV内容は通信しません。

初期状態はメモリー内のみ。再読み込みやタブを閉じると消えます。「この端末にデータを保存する」をオンにした場合だけ、このサイトのlocalStorageに保存します。共有端末では保存をオフにしてください。「データを削除」で保存も消せます。元のCSVファイルは削除しません。

元列CSVも表計算ソフトでの数式実行を防ぐため、記号で始まる文字列を安全化します。バイト単位で同一の原本が必要な場合は元ファイルを保管してください。UTF-8 CSV・1ファイル25MB以内に対応。

## 確定申告について

申告準備のための集計ツールです。税額の計算や申告書作成には対応しません。経費、他社収入、控除、税区分などは別途整理し、帳簿や明細と照合してください。

[国税庁：個人で事業を行っている方の記帳・帳簿等の保存](https://www.nta.go.jp/taxes/shiraberu/shinkoku/kojin_jigyo/index.htm)

## ローカル利用・開発

`index.html` を直接開いても利用可能です。ビルド・依存ライブラリーのインストールは不要です。スクリプトは `core.js`（CSV・集計）と `app.js`（画面・入出力）に分かれています。新しいタブも同じ集計処理を利用して追加できます。

テスト：`node tests/core.test.cjs`

GitHub Pages：Settings → Pages → Deploy from a branch → main / (root)。

Uberの公式製品ではありません。
